Summary

Most AI advice is theoretical. I build the actual thing — and then document it, train the team, and make sure it still works six weeks later.

I came up through design — 20 years of it — then crossed into marketing, then marketing operations, and now I'm building AI systems. That sequence matters more than it looks: design thinking is how I structure problems, it just shows up as workflow architecture now instead of layout grids. Marketing ops is where I learned where the real work accumulates: reporting that takes all day, handoffs that break quietly, data that means something only if you know where to look. I got good at finding those places and automating them. Now I do it with AI — building systems that are still running six weeks later, that someone besides me knows how to use, and that are actually connected to the things they need to connect to. The value is the architecture and the implementation. Prompting is the easy part.

Personal Builds
Roux — AI Meal Planning System
Built on Claude Code · Melsplains · Publicly released

File-based AI meal planning system designed for non-technical users. Two-tier distribution: Simple (claude.ai prompt templates, no setup required) and Build Your Own (Claude Code with local file context, full customization).

Architecture: household profile, pantry inventory, and weekly store deals stored as local markdown files — persistent context across sessions without cloud storage. Custom slash commands (/deals, /plan, /shop, /inventory-add) drive a full weekly meal planning rhythm.

Integrations: AnyList via MCP (pushes grocery lists and meal plan to mobile app); iOS Shortcut for one-tap home screen access. Publicly documented with setup guide, shortcut guide, and landing page.
